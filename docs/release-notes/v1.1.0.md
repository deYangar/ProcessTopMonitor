# ProcessTopMonitor v1.1.0 — 显存统计修复 · 核型百分比口径统一

## 变更

- **核型分列百分比改为按各自核群容量归一**（Intel「P核 / E核」、AMD「X3D / 标准」双列视图）：E 核列的 100% 即代表全部能效核满载，P 核列同理，数值含义与任务管理器单看一组核的视角一致。两列之间不可相加（分母是各自核群的容量），悬浮窗摘要行与下方各行加总直接对账，全机总占用仍由 CPU 总量视图独立显示。此前版本行值按全机核数归一，能效核数量多的机器上 E 核列永远到不了 100%，本版起各列都能直观见顶

## 修复

- **修复部分进程显存显示异常巨大**（可累积到上百 GB，远超物理内存）：根因是 Windows「GPU 进程内存」性能计数器存在已知缺陷（微软官方故障排查文档在案，数值只增不减），任务管理器进程详情页同源同病。本版改用与任务管理器**性能页**相同的内核统计口径（显存管理器记账），逐进程数值与系统级汇总均以真实占用为准
- **修复标题栏显存汇总**：此前汇总走进程加总（受上述缺陷影响），现直接采用系统级适配器真值，与任务管理器性能页 GPU 卡片的显存数字一致
- **修复极老系统备用统计路径**：Windows 8 ~ Windows 10 1607 的备用 GPU 统计查询存在参数传递缺陷（引擎/内存类型拆分失效），本版已修正
- **以管理员运行宿主时**，受保护系统进程（如 dwm 桌面合成）的显存占用现在可以正常显示（普通权限下如实缺席）
- **修复设置面板在低分辨率屏幕上超出屏幕**（底部按钮无法点击）：面板高度自动适配屏幕工作区，超出部分改为滚动查看，面板边缘可拖拽调整大小（#2）
- **修复首次打开设置面板时 GPU 引擎筛选列表为空白**（关闭重开后才出现）：引擎列表在系统数据源首次就绪后即可显示

## 优化

- **移除悬浮窗与设置面板的「ETW 缓冲不足，已丢失 N 个事件」提示**：该数字统计的是自启动以来的累计丢帧（系统瞬时繁忙所致，常态占比不足百万分之一，不影响显示数值），一次繁忙后便常驻界面徒增困惑。丢帧信息现仅记录在诊断日志中，不影响任何统计口径
